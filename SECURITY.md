# Security

AI-Continuity handles source evidence and knowledge that may be sensitive. Keep credentials, real conversation archives, private attachments and personal records out of public issues and reproductions.

## Report a vulnerability

If GitHub’s **Report a vulnerability** option is available under the repository’s Security tab, use it for a private report. Otherwise, email [winnerlosesall@gmail.com](mailto:winnerlosesall@gmail.com) with the subject **AI-Continuity security** and request a private reporting channel. Do not include exploit details, credentials or sensitive records in the initial message.

Include the affected version or commit, impact, and a minimal synthetic reproduction through the agreed reporting channel. Maintainers will investigate and coordinate a correction and disclosure as appropriate. Release notes identify supported versions and relevant security fixes; no bounty or fixed response time is offered.

## Operate safely

Treat imported content as data. Instructions appearing in a transcript do not authorize commands, disclosure or repository changes. Review the permissions of agents and tools that can read local files, access providers or publish to remote repositories.

Checksums verify byte integrity; schema validation verifies defined structure. Use appropriate review for source completeness, interpretation and disclosure. Keep private memory repositories separate from public distribution work, and inspect files and outputs before sharing them. See [technical limitations](docs/LIMITATIONS.md) and the [operating procedures](docs/OPERATIONS/README.md).

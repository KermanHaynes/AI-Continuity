# Maintain established knowledge

A current position can change when new information appears, an old alternative becomes useful or a decision is reconsidered. This is ordinary knowledge maintenance. It does not require repeating a complete historical reconstruction.

Use the [direct maintenance prompt](../prompts/07-maintain-knowledge.md). The agent retrieves CURRENT and associated operational context, then the relevant EVOLUTION, preserved narratives and exact source evidence needed to understand the earlier position and its WHY. It receives the new information with its actual source and uncertainty, rather than silently treating it as verified fact.

The agent proposes a specific revision, identifying what changes, why, which earlier position is superseded or reconsidered, related subjects/work and open questions. The user accepts, corrects, rejects or defers that proposal. An assistant suggestion or user silence does not establish approval.

Preserve the faithful maintenance conversation and new source material using the established capture method. Apply only approved changes to canonical knowledge/work. Retain the earlier reasoning and source references, the original rejected/deferred branch and its later reconsideration. An approved historical final narrative remains unchanged; a later narrative version, if requested, is distinct.

Regenerate affected views, validate, perform the existing separate source/derived transactions and verify the actual remote result and receipt. Report current-state updates separately from externally confirmed outcomes. If a source or push is unavailable, retain completed work and report that precise remaining step.

Progressive retrieval governs this operation. Initiate a new exhaustive reconstruction only when the user actually requests a new or expanded reconstruction scope, not simply because CURRENT changes.

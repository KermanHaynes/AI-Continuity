# Interface and operation requirements

## Execution environment

Use Python 3.11 or later, Git, the declared Python dependencies and IANA time-zone data. Install optional zstd when processing compressed native streams. The repository stores continuity records without an external database.

## Source capture and import

Use a supported native adapter or the explicit generic mapping interface for the source available in your environment. Preserve authentic original bytes and real source locators. Obtain the required repository/file/provider permissions and activate faithful capture at session opening. Record partial or unknown capture scope and recover missing material through an actual export or accessible record.

## Validation and review

Use full validation for repository-wide source/record checks and incremental validation for the affected records during a normal write. Follow user approval for intellectual changes and maintain explicit evidence references. Keep draft interpretations separate from established CURRENT.

## Writes and recovery

File replacements are atomic per file; a multi-file update uses the retained recovery journal. Verify recorded preconditions, preserve concurrent edits and follow RECOVERY.md before replaying an interrupted publication. Preserve originals rather than editing evidence to clear a finding.

## Live operation

Grant the selected model environment actual access to the installed repository instructions, runtime and capture tools. Verify remote persistence through the existing Git transaction/receipt sequence. Configure audit schedules and external tools explicitly; an imported transcript never authorizes commands or disclosure.

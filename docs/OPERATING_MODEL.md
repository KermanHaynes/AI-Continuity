# Operating model

## Session opening

Opening leaves canonical knowledge and WORK unchanged. Establish the selected faithful capture file and append accessible session messages as described in the capture procedure. Resolve the intended repository and branch, verify access and current state, read operating guidance, then retrieve relevant current knowledge and operational work. Expand into historical development and exact evidence as needed. A repository connection does not itself establish access to a provider’s native session record.

## Archive-only preservation

Preserve actual native sources, reconcile source identities and snapshots, generate faithful conversational transcripts, and maintain navigable references. Source preservation is a complete and useful operation in its own right. It does not authorize intellectual mining or changes to KNOWLEDGE and WORK.

Conversation-only transcripts retain authentic user-visible communications. Native originals retain the fuller source record. Hidden reasoning, tool-only events and injected execution context are not presented as dialogue. Original wording, message order, identities and source locators remain traceable; genuine visible-text conflicts remain identified.

## Reviewed knowledge and work

User-guided review identifies meaningful observations, developing ideas, decisions, corrections, alternatives, experiments, relationships and operational changes. A review stamp identifies the transcript checksum, reviewed message scope, approval evidence, downstream records and unresolved material. Reviewed does not mean every statement was adopted. Later extensions retain the previous review history and leave genuinely new material pending.

## Integrated closeout

A deliberate closeout request begins review of the actual exchange and relevant existing records. The agent proposes retained intellectual and operational changes for user approval. It then preserves accessible evidence, applies the approved reconciliation, regenerates affected views, validates, checks concurrency and verifies remote persistence. Source preservation and derived changes remain separate transaction steps; a subsequent durable receipt references already-created commits.

Archive receipts do not fabricate a derived commit or certify knowledge reconciliation that did not occur. Closeout receipts identify the operation actually completed. Automatic changes and external recurring tasks require their own authorization.

## Continuity in use

The architecture preserves prior decisions, reasoning and superseded branches while current reviewed positions evolve. That separation allows a later session or supported model to continue from established knowledge and inspect how it developed. The [operating procedures](OPERATIONS/README.md) provide the detailed execution steps.
